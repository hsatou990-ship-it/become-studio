# 運用手順（JSON受領・15秒制作・計測記録・長時間化の課題） 2026-11-27

## 1. ChatGPTからJSONを受け取ったとき（受領だけで完了としない）
CINEMATIC PRO の「外部AIの映像設計を取り込む」に貼り、取り込むと画面に「取り込み報告」が出る。次の6点を確認し、報告をそのままイベント文書に貼る。
1. 仕様への適合性（適合／不適合。不適合なら何も反映されず、エラーの項目名が出る）
2. 未対応の演出指定（live-anim-fusion など。描画には反映されない）
3. 演出の競合（matchCutとmask、maskと場面転換）
4. 実際の描画への反映（場面ごとに「指定→反映」。外れた演出と追加された演出が分かる）
5. 自動調整による変更箇所と理由
6. 全場面を描画して映像が出ることの確認（機械検査のみ）
そのうえで書き出しまで行い、結果（成功／失敗、所要時間、計測値）をイベントに記載する。取り込みだけで「制作完了」とは書かない。

## 2. 15秒の完成動画を作る流れ
実素材（権利情報つき）→ ナレーション取り込み → BGM取り込み（入手元・ライセンス・権利確認）→ JSON取り込み → 取り込み報告の確認 → ブラインド比較セット書き出し → 採点ページで採点 → 答え合わせ → 結果をDrive 07のイベントに保存。

## 3. Androidでの計測記録（書き出し完了時に画面へ自動表示）
フレーム描画の平均・95%点・最大（ms）、書き出し全体の秒数、ヒープ最大（Chrome系のみ）、端末メモリ、コア数、解像度、動画長。
記録は、機種名・OS・Chromeのバージョン・解像度（720/1080）とともに、イベント文書へ貼る。目標値は未設定（実測が出てから、動画長ごとの許容を決める）。

## 4. 長時間動画への拡張で想定される問題（見積りの算出は計算コード。実測ではない）
| 長さ | フレーム数 | ミックス音声(2ch,float32) | ナレーション(1ch) |
|---|---|---|---|
| 15秒 | 450 | 約5.5MB | 約2.7MB |
| 30秒 | 900 | 約11MB | 約5.5MB |
| 60秒 | 1800 | 約22MB | 約11MB |
| 90秒 | 2700 | 約33MB | 約16.5MB |
1フレームのキャンバスは1080x1920で約7.9MB（メモリ上）。
- 書き出し時間: 所要＝動画秒×倍率。倍率3なら90秒で約4.5分。端末の発熱・スロットリングで倍率が悪化する可能性がある。画面オフ・バックグラウンド化で中断される恐れがあるため、長尺は画面を点けたまま実施する。
- メモリ: 実素材クリップを複数同時に保持するため、素材が増えるほどヒープが増える。シークの待ち時間が書き出し時間の大部分を占める可能性が高い（未計測）。
- 場面数: 長尺では場面が増え、演出の自動調整（強い演出の連続防止・静の場面の確保）の影響が大きくなる。90秒（最大40場面）での検証は未実施。
- 音声: ナレーションが長いと字幕の自動同期のずれが蓄積しやすい（15秒でのみ検証済み）。BGMが短い場合は終わりが無音になる。
- 品質: 長尺ほど同じ演出の繰り返しが目立つ。60秒以上はA/B/C比較を15秒で確認した後に行う。
- 段階: 15秒で品質と計測を確認 → 30秒 → 60秒 → 75〜90秒。各段階で書き出し時間とヒープを記録し、前段階の2倍を超えたら原因を調べてから進む。

## 5. 安全に関する確認状況
- AAC関連: リポジトリにaac.jsは存在しない（git管理外であることを確認）。Service Workerの旧キャッシュ削除・再キャッシュ防止・404時の非キャッシュを、旧SWでaac.jsをキャッシュさせた状態から検証（7/7合格、模擬環境）。公開URLが実際に404を返すかは、この環境から確認できません（オーナー側確認が必要）。
- BGM取り込み: 形式（音声拡張子/MIME）、サイズ上限40MB、最小サイズ、3秒未満、ほぼ無音、音割れ多数、拍の確信度を検査。拍を確信できない場合は拍吸着を使わず、台本どおりの長さで編集する。確信度の閾値（1.8）は合成音源（キック音は187以上、ノイズ1.37、拍なしパッド1.0）で決めた暫定値で、実際の楽曲では未検証。
