# AUTOMATION ENGINEER の機能（become-system-engineer に統合。個別スキルは追加しない）

版: v0.1（2026-11-28）。設計のみ。この資料の機能の多くは、まだコードに実装していない。実装は、承認範囲の確認後に、小さく分けて行う。必要なときだけ読む。

## 1. 担当
制作工程の連携、ワークフロー、状態管理、依存関係、安全な再試行、途中からの復旧、重複処理の防止、自動保存、通信枠と容量の管理、中断と再開、完成条件の確認。

## 2. 工程の状態（8種）と遷移
未実行、実行中、成功、失敗、確認待ち、再実行可能、中断、復旧済み。
- 未実行 → 実行中 → 成功／失敗／確認待ち／中断
- 失敗 → 再実行可能（失敗した工程だけ。取得済み素材、音声、字幕は保持）
- 中断・異常終了 → 復旧済み（保存した地点から再開）
- 確認待ち → 成功（人の確認の後のみ）
- 禁止する遷移: 未実行から成功へ直接、確認待ちの自動通過、成功した工程の無断の再取得（重複ダウンロード）。
表示は、この状態から作る。表示用の別の文章を持たない。

## 3. 自動停止の条件（無制限の再試行、権限の自己拡大は禁止）
認証エラー、権利未確認、通信枠の超過、費用が発生しうる場合、承認範囲外の通信は、自動的に停止して報告する。通信エラーは、一時的（再試行可、回数に上限）、恒久的（再試行しない）、枠・認証（停止）に分類する。容量不足とメモリ不足は、書き込みや読み込みの前に検出する。

## 4. 24工程と現状（2026-11-28 時点。実機の完成は未確認）
- 現行エンジンにある（模擬環境で確認）: 台本・設計JSONの取り込み、素材検索、候補比較、採用素材の取得、ライセンス情報の登録、音声の取り込みと解析、発話区間の検出、字幕と音声の同期、素材の自動配置、構図の自動調整、色と演出の描画、音響処理、MP4書き出し、保存と復元。
- 部分的: 品質検査（監督レビューは機械測定のみ。視聴評価は人）、問題箇所の改善（手動）。
- ない: 台本の意味・目的の自動分析、高品質なナレーション生成（Rikoの声が基準。低品質な声へ自動で切り替えない）、ストーリーボードの自動生成、検査から改善までの自動ループ。

全工程の接続は、15秒作品の実機での完成と書き出しの後に、段階的に行う。

## 5. 現行環境で使える仕組み（確認済みのもの）
- テストコード: Playwright による模擬試験（tab1、ts1 など）。
- Hooks: 作業の終了時に、未コミットの変更を知らせるフックが、このセッションで動作している。安全条件のコード化（通信先の許可リスト、通信枠、キーの除去）は、アプリ内の機能と試験で強制する。
- サブエージェント: 独立した確認（高リスクの検証）に使える。承認範囲は変えない。
- 確認できていないもの: 新しいセッションでのスキルの自動発動（クローンでの復元確認のみ予定）。

## 6. 開発の標準の流れ
課題発見 → スキル選択 → コード確認 → 再現 → 原因分析 → 失敗テスト → 承認範囲内の最小修正 → 回帰 → コードレビュー → 安全性検査 → 実機確認 → 記録 → 次回へ反映。
