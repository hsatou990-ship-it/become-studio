# 映像内容の自動分析（比較と測定計画。モデル取得・コード変更は未承認）
登録日: 2026-11-28。状態: 計画のみ。r11-am の実機検証が最優先。

## 目的
タグだけの素材選定から、映像の内容を理解した選定へ。症状の例（オーナーの実機）: 時計の場面にコーヒーと眼鏡、一歩の場面に木と花。r11-am はタグの関門で減らしたが、映像は見ていない。

## 候補の比較（既存の調査結果。未測定は「確認できません」）
- A. モデルなし（メタデータとフレームの統計）: 追加費用0円、追加の取得なし、Android可。精度は低い（物体の種類は分からない）。速度・メモリは軽い見込みだが、測定していない。向く用途: 明るさ、動き、人物の有無の粗い推定、重複の検出。
- B. CLIP系（OpenAI CLIP）: ライセンスはMIT（一次: 配布元の表記）。英語中心で、日本語の台本は英語へ変換が必要。Android Chromeでの速度、モデルのサイズ、メモリは確認できません。実行の枠組みは Transformers.js（Apache-2.0。既定はWASM、WebGPUは実験的）。
- C. SigLIP多言語（ONNX版）: Apache-2.0の表記。ただし元モデルのライセンス、サイズ、日本語の精度は確認できません。
- D. Jina CLIP v2: CC BY-NC。商用不可のため、候補から外す。
- E. 日本語CLIP（Mitsua）: CC BY-SA。精度が弱いとの情報。採用には慎重。
- F. MobileCLIP: 重みのライセンスが不明。使えない（確認できるまで）。
- G. Chromeの内蔵AI: Androidでの画像理解の提供状況は、確認できません。
- H. Gemini API: 保留中（承認なし）。0円の範囲も、確認できません。

## 比較する観点（測定の項目）
Android互換、認識精度、処理速度（1素材あたりの秒）、モデルのサイズ（MB）、メモリ（ピーク）、発熱、ライセンス、費用、オフライン可否、日本語対応。

## 測定計画（承認後。承認までは何も取得しない）
1. 試験集合: オーナーの実機で外れた例（時計×コーヒー・眼鏡、一歩×木・花）と、合っていた例。各場面の台本文と、採用された素材から抜いたフレーム数枚。
2. 指標: 場面の意図に合う／合わないの正誤。人間（オーナー）の正解ラベルと比較。機械の点数だけで合格にしない。
3. 実機測定: 同じ端末で、速度・メモリ・発熱。模擬環境の結果は実機の保証にしない。
4. 判定の基準: 精度が上がり、かつ1080p書き出しと端末の安定性を損なわないこと。損なう場合は採用しない（品質優先）。
5. 0円の維持: 追加費用が出る方法は、承認なしに使わない。
