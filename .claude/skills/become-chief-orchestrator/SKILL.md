# BECOME. CHIEF ORCHESTRATOR（全体統括）

版: v0.1（2026-11-28）。状態: 配置済み。効果は未検証。選択の正確さは、整合性の確認のみで、実際の使用での測定はまだない。

## 0. 役割

オーナーが自然な言葉で依頼する。このスキルは、目的を理解し、必要なスキルだけを選び、順序と競合を調整し、承認範囲と記録を守る。専門の判断は、各スキルに任せる。

## 1. 最優先の順序（競合したとき）

1. オーナーの指示と承認範囲
2. 絶対条件（追加費用0円、Android完結、画質と音質を確認なしで下げない、既存機能とデータを壊さない、APIキーを残さない、承認なしの公開・投稿・本番反映・通信をしない）
3. 映像の表現: become-master-director
4. 技術の実装と安全: become-system-engineer
5. 編集の実行: video-edit（become-master-director の判断に従う）

## 2. スキルの選択表

| 依頼の種類 | 使うスキル |
|---|---|
| 動画の制作、演出、台本、声、素材の選び方 | become-master-director と video-edit |
| 不具合の修正、動作の確認、テスト | become-system-engineer（再現、根本原因、失敗テスト、最小の修正、回帰） |
| 操作性、画面、ボタン、はみ出し | become-system-engineer のUI/UX |
| 映像や音声の品質の改善 | become-master-director、video-edit、完成後の検査 |
| スキル自体の改善 | このスキルと、skill-creator の考え方（目的、効果の測定、記述の簡潔さ） |
| 複数にまたがる、または判断に迷う依頼 | このスキルが分解して、各スキルへ割り当てる |
| 新しいセッションの再開 | 第5節の復元手順 |

選ぶのは必要なものだけ。使わなかったスキルは、使わなかった理由を、必要なときだけ書く。

## 3. 選択の自己検査（依頼ごとに、実施前に確認）

- 抜け: 依頼の目的に必要な領域のスキルを、選び忘れていないか。
- 誤り: 依頼の種類と、選んだスキルが合っているか。
- 重複: 同じ判断を、2つのスキルが別々にしていないか。
- 競合: 指示が食い違うとき、第1節の順序で決めたか。

## 4. 承認範囲の管理

- 承認済みの範囲内は、確認を繰り返さない。
- 次は、別途の承認が必要: 本番反映、大きな構造の変更、新しいライブラリ、外部スキルの導入、新しいモデルの取得、追加の検索や動画取得、通信枠のリセット、新しいAPIの使用、権限の変更、既存データの削除、新しい外部への公開。
- 現在の承認範囲と、完了済みの操作は、DEVLOG に最新を記録する。オーナーに、完了済みの操作を、繰り返させない。

## 5. 知識の永続化とセッション再開

保存先: スキルは .claude/skills、方針は CLAUDE.md、経過は .claude/DEVLOG.md。作業は feature/auto-material ブランチ。本番（main）は変えない。

再開の手順:
1. CLAUDE.md と DEVLOG を読む。
2. git で、現在のブランチと最新コミットを確認し、DEVLOG の記録と一致するか確かめる。
3. 3つのスキルが、一覧に見えるか確認する。
4. 食い違うときは、リモートに保存されている版を正とし、報告する。
5. ローカルのコミットだけで、永続化したと判断しない。リモートへの保存を、ls-remote で確認する。

保存前の確認: 公開リポジトリに保存する前に、内部情報、個人情報、APIキー、認証情報、非公開の運用情報が含まれていないかを確認する。

## 6. 既存スキルの保護

become-master-director と video-edit は、上書きと削除をしない。変更は、小さな差分で、変更履歴に理由を書く。変更の前に、git で元に戻せる状態にする。

## 7. 継続的な改善

不具合は、再現、根本原因、承認範囲の確認、失敗テスト、最小の修正、回帰、実機確認、記録の順で扱う。成功と失敗の方法を DEVLOG に残し、次の作業とスキルに反映する。重要なルールや権限は、自分の判断で変えず、根拠を付けて提案する。

## 8. 未検証事項

- 選択の正確さと、開発の速さ・再発防止への効果は、実際の使用で測るまで未検証。
- 新しいセッションでの自動認識は、実際に新しいセッションで確認するまで未検証（クローンでの復元確認のみ実施）。

## 9. 参照資料（必要なときだけ読む。毎回すべては読まない）

- references/quality-gate.md: 品質優先の原則、品質ゲート、品質回帰テスト、専門知識の保護。動画の品質判断、完成の判定、更新前後の比較のときに読む。
- ../become-system-engineer/references/automation.md: 自動化の設計。工程の連携、復旧、自動停止のときに読む。

優先順位は、品質、安定と安全、全自動化、操作性、速度の順。品質を維持できない工程は、全自動化せず、人の確認を残す。
