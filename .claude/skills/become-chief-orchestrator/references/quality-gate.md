# 品質優先の原則と品質ゲート（become-chief-orchestrator 参照資料）

版: v0.1（2026-11-28）。オーナー指示「QUALITY FIRST」の反映。必要なときだけ読む。

## 1. 優先順位
1. 映像・音声・作品の品質
2. システムの安定性と安全性
3. 全自動化
4. 操作性
5. 処理速度と効率化

競合したら上を優先する。品質を維持できない工程は、無理に全自動化せず、人の確認を残す。

## 2. 統合した能力（新規スキルは作らず、既存スキルへ割り当て）
- Quality Gate: 本資料。判定の実行は become-system-engineer（機械検査）と become-master-director（演出の判断）。
- Quality Regression Testing: 本資料の第4節。
- Creative Evaluation: become-master-director の第14b節（100点満点、目標95点）。実際の視聴評価なしに点数を確定しない。
- Quality-aware Optimization: 速度、容量、発熱のための変更は、映像・音声の品質への影響を、先に比較してから採用する。画質や音質を下げる変更は、オーナーの事前確認が必要。
- Knowledge Preservation: 第5節。
- Human-in-the-Loop: 権利確認、重要な品質判断、公開・投稿は、人の確認を省略しない。

## 3. 品質ゲート
完成作品が基準を満たさないとき:
1. 完成扱いにしない。問題の箇所（場面、時刻、項目）を特定する。
2. 承認範囲内で改善し、再検査する。
3. 改善できないときは、無理に続けず、理由と現状を報告する。

機械で測れる項目（音割れ、黒フレーム、フリーズ、音声・映像の欠落、字幕の同期、MP4の再生可否、解像度、処理時間、通信量、手動操作の回数）と、人が見る項目（映像と台本の意味の一致、映像品質、ナレーション品質、被写体の見切れ、演出、権利情報）を、分けて報告する。人が見る項目は、オーナーが見るまで「未評価」。自動検査で判断できない項目を、合格にしない。メモリ使用量と発熱は、実機で測るまで「確認できません」。

## 4. 品質回帰テスト（更新の前後で比較）
1. 同一の台本、素材、音声、設定を固定する（データを保存して再利用する）。
2. 更新前と更新後で、同じ工程を実行する。
3. 比較する項目: 映像品質、音声品質、字幕同期、演出、処理性能、操作性。
4. 機械測定と視聴評価を、分けて記録する。
5. 低下が確認されたら、本番反映せず、原因を特定する。
基準となる素材と音声（Rikoのオリジナル音声、V022）の保存場所と版は、DEVLOG に記録する。

## 5. 専門知識の保護
- SKILL.md を短くする場合は、詳細を references に移す。削除しない。
- 変更の前後で、見出しと判断基準の一覧を比較し、欠落がないことを確認してから確定する。
- become-master-director と video-edit は、このやり方でも、本文を上書きしない（変更は差分と履歴で行う）。

## 追記（2026-11-28）: 基準作品の登録条件
音声の比較基準にするには、音声の出所（外部ファイル名とSHA-256／模擬音声）が記録されていること。模擬音声の疑いが残る作品は、映像の技術基準にだけ使い、音声の基準にしない。
